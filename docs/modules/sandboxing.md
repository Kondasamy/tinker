# Sandboxing (`/sandboxing/`)

Decisions for this module only; the shared rules are in `AGENTS.md`.

## Picture

- **The glass room** (`src/components/scenes/sandboxScene.ts`) composes `officeScene` (the front desk renamed OPERATOR, the host SANDBOX) and adds, read off one run up to the current step: a low wall round the yard when the sandbox is on (the operator stays outside), a file door on the belt to the file store (the order system), a network door on an outbound belt to the world with a proxy gate when the proxy holds the secret, and a safe for the secret, inside the yard (in the env) or outside by the proxy. A call a boundary stopped rides to its door with a REFUSED pill. `SandboxStage` (`src/content/sandboxing/kit.tsx`) puts it one tab from the Steps lanes (`sandboxSequence.ts`), where a stopped call is a dashed card stamped REFUSED, Guardrails' stamp. Every chapter keeps the tab in the step state; on phones the pills are left out and the caption carries the readouts.
- **Hero object: the greenhouse-frame glass room** (brick base, green posts, tinted panes), notched at the front so the operator (CAST `operator`, in the employee's place) stands outside at the counter; the safe has a dial and handle, the proxy is a turnstile with its booth.

## Engine (`src/lib/sandboxing/`)

- **A modelled sandbox; no real code runs** (KTD9). `sandbox.ts` is a policy and `exec(policy, command)`, a pure function: mounts with read-only or writable modes (`ro`, `rw`; the longest matching prefix wins), hidden paths, network egress (`off`, an allow-list through a proxy, or `open`) and the secret either in the sandbox's env (a command can read it) or held by the proxy, which adds it to allowed requests and never shows it to the agent. Three file presets (`PRESETS`: `open`, `scoped`, `nodata`, the last with the private data not mounted). The files and their contents are fixtures in `data/sandboxing/files.json`; the token is a stand-in, never a real key. Nothing reaches the disk or the network.
- **The loop is forked from Guardrails'** (`loop.ts`), not a wider tools `Bundle`: one agent, four tools (`run`, `read_file`, `write_file`, `fetch`, in `data/sandboxing/server.json`), the sandbox a host stage around each call. A call the filesystem stops is `denied`, one the egress stops `blocked`; both enter the history and are stamped REFUSED.
- **The signature is what the agent could see** (`turns.ts`): the case, the tools and the history of outcomes (each `tool[:path|:host]:<outcome>`). Policy reaches it only through those outcomes. Host-only settings stay out: the approval mode (a person asked about a blocked fetch) changes what the host does, not what the agent is shown.
- **One merged recording.** Turns live in `data/sandboxing/turns/<chapter>.json` (27 in all), one reviewed file per chapter scenario holding the turns that chapter first needs; a signature is in exactly one file and every run looks up the merged `RECORDING`. Every chapter control has a finite domain (`DOMAINS`, and `WORKBENCH_DOMAINS` for chapter 7's red team), and `tests/unit/sandboxing-coverage.test.ts` runs every combination and fails on any `norecord`, on a signature in two files, on a recorded turn nothing reaches, or past the budget.
- **Chapters 3 and 6 keep the secret in the env**, so the exfiltration attack reads it and reaches the fetch the network stage acts on; with the proxy holding it the attack would stop earlier and the network door would have nothing to show.
- **One suite, two counts** (`data/sandboxing/suite.json`): four attacks (exfiltration, a hidden key read, a system file written, a record smuggled through the allowed host), each with a goal checked against the run's ledger, and two ordinary tasks, each with the tools it needs. `metrics()` gives attack success rate (`asr`) and false-block rate (`fbr`).
- **Chapter 7's puzzle accepts every minimal winning policy** (`workbench.ts` `WINNERS`): every policy the controls can make that stops every attack with the fewest blocked tasks, not one hand-picked answer.
- **Facts about sandboxing** come from `data/sandboxing/facts.json` with source and access date.
